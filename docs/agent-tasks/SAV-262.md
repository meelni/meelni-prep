# SAV-262 — Paid one-time Checkout fulfillment

## Intent

- User request: Complete the launch-readiness program without changing the relaunch flag or taking live-mode actions.
- Product/user outcome: A paid Interview Pass becomes one usable credit exactly once; delayed, unpaid, or failed payments never create spendable credit early.
- Why now: SAV-185 is the next unblocked urgent billing-recovery slice.

## Slice

- Primary slice: Billing, trials, and entitlements.
- Secondary slices: Stripe webhook security and provider normalization.
- Relevant skills: `meelni-vertical-slice-playbooks`, `meelni-linear-workstream`, `stripe-best-practices`, `meelni-engineering-memory`.

- Project: Meelni.

## Scope

- In scope: Authoritative Checkout Session retrieval, complete line-item validation, paid-only fulfillment, delayed-payment event routing, owner correlation, ledger idempotency, tests, and durable contracts.
- Out of scope: Subscription policy, new SKUs, billing UI, refunds or prorations, live Stripe changes, Production data, and launch decisions.
- Assumptions: The existing credit ledger remains the exactly-once mutation boundary; the Interview Pass remains one USD-denominated credit purchased through Checkout `payment` mode.

## Product Lens

- Audience: Individual PM candidates purchasing one interview credit.
- Lever: Monetization trust and paid activation.
- Product Compass note: Payment truth must precede access; retries must converge without customer-visible duplication.

## Technical Plan

- App files: `app/api/webhooks/stripe/route.ts` and its route tests.
- Workflow files: `lib/billing/stripe-checkout-fulfillment.ts` and behavior tests.
- Provider dependencies: Stripe Checkout Session retrieval with expanded line items; signed webhooks; configured Interview Pass price.
- Docs: Checkout fulfillment contract, Stripe test plan/quick reference, launch runbook, and live-mode checklist.

## Validation

- Required: focused fulfillment tests, `npm run test:billing`, `npm run test:api`, type checks, `npm run check:ci`, and `npm run build`.
- Optional/manual: isolated Stripe test-mode immediate payment, delayed success, delayed failure, and replay after repository checks pass.
- Fixtures: Synthetic paid, unpaid, async-success, async-failure, replay, wrong-owner, wrong-price, wrong-quantity, incomplete-line-items, and provider-failure cases.

## Rollout

- Risk level: High correctness risk, low migration risk.
- Backward compatibility: No schema change; existing session-derived grant idempotency keys remain canonical.
- Metrics/events to watch: Failed Stripe event-log rows by stable error code and duplicate ledger grants.
- Follow-up slice: Isolated provider rehearsal remains under SAV-226/SAV-126.
