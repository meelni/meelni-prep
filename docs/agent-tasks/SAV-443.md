# SAV-443 saved-interview processing workspace

## Intent

- User request: keep a saved interview useful while terminal settlement and
  feedback generation are still in progress.
- Product/user outcome: the candidate can confirm the interview is saved, see
  its historical question and round, open only finalized transcript evidence
  when available, understand the current stage, leave, and return later.
- Why now: durable settlement and content-free feedback attempt history are
  available, but the feedback route still collapses transient work into a
  spinner-first status page.

## Slice

- Primary slice: feedback/evaluation vertical slice.
- Secondary slices: authenticated transcript read boundary and feedback UI.
- Relevant skills: Meelni feedback evaluation, UI design system, codebase
  architecture, vertical-slice playbook, engineering memory, Linear workstream,
  and PR preparation.

## Linear tracking

- Project: Interview to Feedback Loop.
- Child deliverable issue: SAV-443.
- Current state at implementation start: In Progress.

## Scope

- In scope: a strict versioned saved-interview projection on transient feedback
  reads; frozen-only transcript access; saved question/round context; bounded
  pending, delayed, retryable, paused, unavailable, and return-later states;
  component, API, browser, responsive, and accessibility regressions.
- Out of scope: score authority, provider calls/configuration, transcript or
  settlement persistence, feedback-stage history storage, alerts, a processing
  redesign outside the feedback workspace, schema migrations, deployment, and
  Production action.
- Assumptions: the existing terminal frozen-transcript query remains the
  evidence authority, and the existing bounded polling/recovery coordinator
  remains the lifecycle authority.

## Product lens

- Audience: authenticated candidates returning from a completed mock interview.
- Retention lever: remove ambiguity and dead time between interview completion
  and visible feedback while preserving trust in saved evidence.
- Product Compass note: make the transition useful and honest; do not imply
  performance, progress, or numerical results before validated feedback exists.

## Technical plan

- App: extend the feedback lifecycle GET, add a saved processing workspace,
  retain the projection across rolling-compatible polls, and opt feedback
  transcript reads into an explicit frozen scope.
- Core: add a closed `saved-interview.workspace.v1` decoder.
- Data/provider dependencies: reuse the single historical session/question join
  and existing frozen transcript read; no provider dependency and no migration.
- Docs: update feedback and transcript contracts and add an OpenSpec delta.

## Validation

- Required: focused core/component/API/page tests, browser Chromium coverage at
  mobile and desktop widths with Axe, typecheck, build, and `verify:agent`.
- Fixtures: synthetic questions and transcript turns only; no customer content,
  provider payload, room, user, or raw generation-event fields.

## Rollout

- Risk: medium; authenticated read projection and transient UI only.
- Backward compatibility: the lifecycle field is optional and the client keeps
  the last accepted projection when a rolling response omits it. The default
  transcript route remains compatible; feedback explicitly requests `frozen`.
- Evidence to watch: hosted component/API/browser/typecheck/build gates and
  customer-safe lifecycle state, without content-bearing telemetry.
- Follow-up: processing-stage visualization may consume the existing
  content-free attempt history in a separately owned slice.
