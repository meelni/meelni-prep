# SAV-383 Agent Task Intake

## Intent

- User request: Make the authenticated interview end-to-feedback path reliable
  and fast after a Production interview remained on “Saving your interview.”
- Product/user outcome: Once End Interview is accepted, a candidate does not
  depend on one opaque worker attempt or an open browser to receive feedback.
- Why now: The Production trace terminalized the session but skipped feedback
  dispatch after runtime settlement degraded; the previous recovery scan no
  longer selected the terminal session.

## Slice

- Primary slice: Durable explicit-user-end finalization.
- Secondary slices: feedback outbox recovery, room cleanup, credit convergence,
  lifecycle observability.
- Relevant skills: LiveKit interview runtime, feedback evaluation, codebase
  architecture, vertical-slice playbooks, Linear workstream, engineering memory.

## Linear Tracking

- Project: Meelni.
- Parent slice issue: SAV-365.
- Child deliverable issue: SAV-383.
- Current Linear state: In Progress.

## Scope

- In scope: Stable Inngest checkpoints for runtime settlement, terminalization,
  feedback dispatch, cleanup scheduling, and credit convergence; terminal
  undispatched-feedback recovery; allowlisted stage reasons; replay fixtures;
  an End Interview escape hatch that remains available during reconnect.
- Out of scope: Transcript eligibility policy, scoring/rubric changes, committed
  writer watermarks, Production deployment, and provider credential changes.
- Assumptions: The session lifecycle and feedback outbox remain canonical truth;
  every stage operation remains idempotent.

## Technical Plan

- Replace the single `settle-finalize-and-dispatch` step with stable versioned
  stage IDs.
- Return JSON-only checkpoint summaries so provider replay cannot change types.
- Run feedback dispatch, cleanup scheduling, and credit convergence as sibling
  checkpoints after terminal truth; one failure cannot erase successful siblings.
- Re-enter feedback through the durable feedback recovery workflow rather than
  carrying a rich database record between provider checkpoints.
- Bound the provider event-send attempt at three seconds. If it stalls or
  fails, mark only the still-current fenced outbox claim failed so immediate
  retry does not wait for the two-minute abandoned-claim lease.
- Extend the minute recovery scan to terminal sessions with a retryable eligible
  feedback outbox and skip the no-longer-needed provider settlement round trip.

## Validation

- Required commands: focused durable-workflow tests, workflow suite, operations
  suite, typechecks, lint, build, and interview resilience suite.
- Regression fixtures: runtime degradation, finalization failure, dispatch
  failure, cleanup failure, credit failure, terminal replay, missing evidence,
  terminal undispatched-feedback recovery, and reconnecting room controls.
- Privacy: Stage telemetry contains only an allowlisted reason and an owned
  session correlation UUID; no identity, transcript, feedback, or provider data.

## Rollout

- Risk level: Medium-high. This changes the durable workflow graph and recovery
  selection, but not terminal or feedback eligibility rules.
- Backward compatibility: Existing completed runs remain complete. An in-flight
  legacy run may enter the new idempotent steps after deployment without
  duplicating terminal truth or feedback dispatch.
- Metrics to watch: per-stage failure/retry counts, terminalization latency,
  feedback dispatch latency, terminal undispatched count, cleanup lag, and
  credit-convergence lag.
