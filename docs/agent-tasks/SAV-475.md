## Implementation Record

- The gate accepts only the concrete session-local
  `DirectorRecommendationStore`; there is no callback, coroutine, provider, or
  network seam on the decision path.
- The exact server-owned flag is read on every serialized mutation admission.
  Revocation returns before the store is read, including for a recommendation
  that became ready before revocation.
- `commit_interviewer_move` can consume only probe, clarify, challenge, or
  transition advice. `request_graceful_close` can consume only close advice.
- Accepted commit advice produces a separate controller-validated effective
  request. It preserves the original call, idempotency, deadline, writer,
  lifecycle, and revision identity while changing the move type, target, and
  their required closed reason code, then recalculates the effective digest.
- The original request remains the idempotency authority. Controller denial of
  an effective request is non-mutating and retries the original deterministic
  request. Ignore, reject, telemetry failure, revocation, or absence never asks
  the controller for fallback.
- Consumed and pending influence state is bounded and cleared on authority
  advance, settlement, and shutdown. Canonical delivery attribution is read
  only from the controller ledger.
- Application wiring remains `adapter=None`; no live Director work can start
  and no Preview, Production, provider, environment, or launch state changed.
