# SAV-446 Agent Task Intake

## Intent

- User request: Produce deterministic, provider-free feedback bakeoff and queue
  evidence without changing runtime configuration or activation.
- Product/user outcome: Give the owner reproducible evidence for a later
  staging decision while preserving the durable feedback-generation contract.
- Why now: The bounded generation deadline exists, but output-ceiling and queue
  tradeoffs need an aggregate comparison before any live or runtime work.

## Slice

- Primary slice: Feedback evaluation and calibration.
- Secondary slices: Pure queue analysis and provider-free tooling.
- Relevant skills: Start routing, Linear workstream, feedback evaluation,
  codebase architecture, vertical-slice playbooks, engineering memory, and PR
  preparation.

## Linear Tracking

- Project: Meelni.
- Parent slice issue: Phase 3 feedback evaluation.
- Child deliverable issue: SAV-446.
- Current Linear state: In Progress.

## Scope

- In scope: Extend the existing synthetic calibration replay, round-trip output
  through the real parser, measure aggregate output bounds, simulate queue
  stages against the durable deadline, and commit reproducible content-free
  evidence.
- Out of scope: Live or paid model calls, provider credentials/configuration,
  real prices or traffic, customer data, queue or token-cap changes,
  Production mutation, deployment, default activation, and launch action.
- Assumptions: Candidate latency and cost units are explicit synthetic inputs;
  they are comparison aids rather than observations or recommendations.

## Product Lens

- Audience: The product owner reviewing post-interview feedback reliability.
- Activation/retention/monetization/growth lever: Trust and retention through
  feedback that remains bounded under plausible burst conditions.
- Product Compass note: Prefer reversible staging evidence while keeping live
  provider choice and launch authority human-owned.

## Technical Plan

- Likely app files: None; no app entrypoint or runtime configuration changes.
- Likely package/workflow files: Existing calibration module, a pure queue
  simulator, closed config/report parser, and a thin canonical report command.
- Data or provider dependencies: Fully synthetic fixtures only; no database,
  network, provider, credential, or customer-data dependency.
- Docs/decisions to update: Evaluation calibration contract and runbook,
  tooling index, this intake, and the canonical aggregate evidence report. No
  new decision is required because the accepted program already bounds this
  analysis slice.

## Validation

- Required commands: Canonical report build/verify, focused bakeoff tests,
  calibration/workflow/operations suites, TypeScript checks, build, and agent
  verification.
- Optional/manual checks: Confirm the exact main merge base, inspect the report
  for content/provider leakage, verify runtime configuration is untouched, and
  monitor hosted checks to a terminal result.
- Fixtures or regression tests needed: Separate evidence validity from parser
  acceptance, enforce closed provider-neutral config, prove deterministic
  report hashes, preserve stage-separated queue timing, and prove no activation.

## Rollout

- Risk level: Low; additive provider-free analysis and documentation only.
- Backward compatibility: Feedback runtime, model/tier, token ceiling, queue,
  deadline/retry behavior, and defaults remain unchanged.
- Metrics/events to watch: None in Production. Review synthetic deadline success
  and stage distributions before designing any staging experiment.
- Follow-up slice: Owner-reviewed staging design and separately authorized live
  evidence, if requested; this artifact grants neither.
