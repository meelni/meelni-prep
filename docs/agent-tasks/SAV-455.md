# SAV-455 Agent Task Intake

## Intent

- User request: render versioned, generated synthetic feedback artifacts in a local-only Feedback Lab using the same feedback compositions customers see.
- Product/user outcome: developers can select a named provider-free scenario, compare its expected closed outcome with the rendered customer outcome, and inspect deterministic responsive and accessibility evidence without creating customer or provider state.
- Why now: SAV-453 is consolidating customer feedback into three closed outcomes, and SAV-454 is supplying production-shaped synthetic artifacts for repeatable inspection.

- Primary slice: agent tooling and feedback-evaluation UI verification.
- Secondary slices: build-excluded browser harness, accessibility, design-system conformance, and CI evidence.
- Relevant skills: `meelni-linear-workstream`, `meelni-ui-design-system`, `meelni-feedback-evaluation`, `meelni-codebase-architecture`, `meelni-vertical-slice-playbooks`, `meelni-engineering-memory`, and `meelni-pr-prep`.

## Technical Plan

- Likely app files: reuse `components/feedback` compositions without adding an app route.
- Likely package/workflow files: `tests/browser/harness`, focused Playwright specs and support, root scripts, the existing browser QA runner/CI lane, and operations documentation.
- Data or provider dependencies: `@meelni/test-fixtures` exports `SyntheticFeedbackScenarioV1`, `SyntheticFeedbackArtifactV1`, `SyntheticFeedbackManifestV1`, and their fail-closed decoders; core exports `FeedbackCustomerProjection`, `FeedbackScorecardView`, `FeedbackCoachingReviewView`, and `toFeedbackCustomerProjection`. No network or provider credentials.
- Docs/decisions to update: document how to generate, add, open, and diagnose scenarios. No new architecture decision is expected because the lab follows accepted build-excluded harness and core-owned projection boundaries.

## Validation

- Required commands: focused Feedback Lab unit/browser coverage, design-system guardrails, `npm run typecheck`, test typecheck, lint, `npm run test:feedback`, `npm run verify:agent`, and hosted checks.
- Optional/manual checks: inspect deterministic screenshots at mobile and desktop widths and exercise scenario selection/citation controls by keyboard.
- Fixtures or regression tests needed: generated terminal artifacts from SAV-454 plus lab-owned processing/loading and malformed inputs; assertions must fail on expected-artifact-rendered outcome divergence and on Partial scorecard or score leakage into scoreless outcomes.

## Rollout

- Risk level: low application-runtime risk and medium tooling/contract risk.
- Backward compatibility: no Production bundle or route change; historical partial-scorecard storage remains immutable and is projected scorelessly by core.
- Metrics/events to watch: hosted browser failures, artifact/manifest decoder failures, customer-outcome mismatches, accessibility regressions, and accidental provider/network activity.
- Follow-up slice: none in SAV-455; future synthetic scenarios are added through the SAV-454 registry and regenerated through its versioned command.
