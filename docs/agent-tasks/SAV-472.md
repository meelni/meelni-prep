## Product Lens

- Audience: authenticated PM candidates completing a full voice interview.
- Activation/retention/monetization/growth lever: more reliable and adaptive
  interview pacing without mid-session teaching or scoring.
- Product Compass note: the tools expose bounded interviewer decisions only.
  They do not evaluate the candidate, reveal chain of thought, or move feedback
  into the live interview.

## Technical Plan

- App boundary: extend the existing HMAC-authenticated internal transcript route
  with a metadata-only current-writer lifecycle reader. The tool layer receives
  only its already trusted, versioned local lease.
- Likely package/workflow files: a Python session-local tool adapter under
  `agent/shared`, the existing controller/runtime adapter, the thin full-
  interview entrypoint, public pinned LiveKit function-tool wiring, focused
  Python tests, benchmark fixtures only if selection coverage requires them,
  and package scripts for portable test coverage.
- Data or provider dependencies: the runtime lifecycle reader performs one
  bounded read through the existing authenticated server/database boundary;
  tools themselves have no HTTP/database/provider adapter. Validation never
  calls a provider or uses customer data.
- Docs/decisions to update: accepted stateful-interviewer contracts, a SAV-472
  decision/OpenSpec change, runtime configuration and operations runbook, this
  task record, and durable engineering memory.

## Implementation Record

- Added exactly five public pinned-LiveKit tool descriptors backed by one
  session-local adapter, 150 ms deadlines, serialized mutation, deterministic
  controller policy, bounded idempotency, privacy-safe telemetry, and a
  three-call turn budget.
- Added reader-first lifecycle authority: locked writer-registration receipt,
  separate authenticated current-writer read, four-second local lease,
  one-second refresh cadence/deadline, irreversible non-active fencing, and
  safe controller invalidation on refresh loss.

  selection before speech. The first failed tool or three-step overflow admits
  one deterministic controller fallback move, fences later tools, permits one

  single-use and completion still requires exact opaque object identity.
