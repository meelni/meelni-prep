# SAV-399 Agent Task Intake

## Intent

- User request: Release the setup page's microphone permission stream before
  launching an interview.
- Product outcome: A PM candidate never has an unowned microphone capture left
  active by setup, including after a delayed or failed start.
- Why now: The permission probe discarded its `MediaStream`; every later setup
  outcome could leave the browser or OS microphone indicator active.

## Slice

- Primary slice: Interview Session setup and launch lifecycle.
- Secondary slices: Permission and recovery UI behavior; LiveKit ownership
  boundary.
- Relevant skills: Linear workstream, vertical-slice playbooks, UI design
  system, and LiveKit interview runtime.

## Linear Tracking

- Project: Meelni.
- Parent slice issue: SAV-365.
- Child deliverable issue: SAV-399.
- Implementation start state: In Progress.

## Scope

- In scope: Stop every permission-probe track before validation or network
  launch continues; serialize repeated starts; clean a late permission result
  after unmount; preserve all setup recovery states.
- Out of scope: Reusing the probe stream in LiveKit, changing browser
  permission policy, changing session/token contracts, deploying, or mutating
  provider and Production configuration.
- Assumptions: LiveKit continues to create and own its room microphone track;
  the setup probe proves capability only.

## Product Lens

- Audience: Authenticated PM candidates starting a voice mock interview.
- Activation/retention/monetization/growth lever: Trustworthy activation and
  interview-start recovery.
- Product Compass note: This is a privacy and reliability correction, not a
  new launch capability or launch-gate decision.

## Technical Plan

- Keep the permission probe inside `app/setup/setup-content.tsx` and release
  all returned tracks before building or validating the session payload.
- Add an imperative in-flight guard because React disabled state is not a
  same-tick concurrency primitive.
- Stop a stream that resolves after unmount and do not continue to validation
  or `/api/session/start` from that stale handler.
- Add a rendered setup-flow behavior suite covering success, timeout, server
  errors, tier/quota responses, validation, denial, repeated clicks, and
  unmount.
- Add the suite to `npm run test:auth-ui`.

## Validation

- Targeted setup-content behavior suite.
- Authenticated UI and interview-start API/workflow regressions.
- Typecheck, test typecheck, lint, build, and `npm run verify:agent`.
- Diff review for privacy, races, React Strict Mode/unmount behavior, and
  accidental LiveKit ownership changes.

## Rollout

- Risk level: Low to medium; local browser resource lifecycle changes before
  the existing start workflow.
- Backward compatibility: Session payloads, stable start-attempt IDs,
  analytics, validation, credit/quota behavior, and LiveKit room ownership are
  unchanged.
- Metrics/events to watch: Existing content-safe interview start stage and
  launch outcome events only; no new telemetry.
- Follow-up slice: None expected for SAV-399.
