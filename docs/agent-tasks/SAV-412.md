# SAV-412 Agent Task Intake

## Intent

- User request: Make the authenticated End Interview settlement request reach
  the registered LiveKit worker and stop speech from racing past the End cutoff.
- Product/user outcome: An active interview settles its durable transcript at
  the accepted End cutoff without a later interviewer turn being submitted to
  a session that is already closing.
- Why now: The sanitized SAV-410 Production ordering returned
  `runtime_not_ready` in about 205 ms despite an active writer, then rejected a
  later interviewer turn as `session_closed`.

## Slice

- Primary slice: Authenticated interview runtime settlement.
- Secondary slices: LiveKit presence reconciliation, transcript outbox cutoff,
  durable user-end finalization, and runtime operations.
- Relevant skills: LiveKit interview runtime, codebase architecture,
  vertical-slice playbooks, Linear workstream, engineering memory, and PR prep.

## Linear Tracking

- Project: Meelni.
- Parent slice issue: SAV-410.
- Child deliverable issue: SAV-412.
- Current Linear state: In Progress.

## Scope

- In scope: Exact writer/room/session/generation correlation, a targeted
  server-authored settlement request when the transient readiness projection is
  absent, synchronous input/output fencing on a trusted request, bounded control
  settlement capacity, and sanitized ordering/deadline regressions.
- Out of scope: Feedback eligibility or marker policy, historical session
  repair, participant data-publish capability, demo runtime behavior, provider
  mutation, Production deployment, and launch gates.
- Assumptions: A registered current writer generation proves the durable
  logical runtime correlation but is not a LiveKit participant identity. The
  LiveKit server can target a participant only after provider-owned identity
  reconciliation; terminal truth and cutoff admission remain owned by the
  database workflow.

## Product Lens

- Audience: PM candidates ending an authenticated live interview.
- Activation/retention lever: Preserve trust at the feedback handoff by saving
  the evidence the candidate just created.
- Product Compass note: The agent remains an interviewer during the session;
  End is a hard conversational cutoff and feedback remains post-interview.

## Technical Plan

- Require the current durable writer generation, then reconcile one exact
  provider-owned agent identity for the same room before sending one reliable,
  targeted settlement packet. Never derive that target from the random writer
  UUID.
- Avoid treating a missing transient readiness projection as proof that a known
  writer is absent, while failing closed on missing or ambiguous agent identity.
- Seal agent turn production synchronously after validating the server-authored
  request and before interrupting speech or scheduling asynchronous settlement.
- Preserve reserved settlement capacity and the existing outer deadline,
  acknowledgement, retry, and generation fences.
- Update the completion/transcript contracts and operations notes with the
  targeting and End-cutoff behavior.

## Validation

- Required commands: Focused settlement workflow/integration tests, Python
  runtime contract tests, `test:agent`, `test:integrations`,
  `test:python-agent`, `test:interview-resilience`, typecheck, `verify:agent`,
  diff checks, and secret checks.
- Regression fixtures: Missing readiness projection with an active writer and
  exact room agent; wrong room/session/generation; absent or ambiguous agent;
  timeout/provider error; duplicate End; post-End interviewer callback; and a
  busy data lane with reserved settlement control capacity.
- Optional/manual checks: Provider-backed rehearsal remains a separate,
  owner-authorized rollout step.

## Rollout

- Risk level: High because this coordinates server/provider targeting with the
  live agent's transcript cutoff.
- Backward compatibility: Existing packet schema, participant capabilities,
  terminal rows, and fail-closed evidence rules remain unchanged.
- Metrics/events to watch: Settlement outcome and latency, readiness/presence
  reconciliation, durable acknowledgement, post-cutoff local rejections, and
  transcript integrity classification.
- Follow-up slice: SAV-411 owns the distinct interruption-marker/feedback-policy
  issue; SAV-419 owns the pinned dispatch-projection and synchronous callback
  fence amendment; SAV-410 remains open for incident closeout and guarded
  rollout.
