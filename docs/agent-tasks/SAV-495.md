# SAV-495: Launch The Adaptive Interviewer For Production Customers

## Intent

- User request: launch the adaptive interviewer directly in the Production web
  product for all users and use the owner's first real interview as the smoke.
- Owner GO: "I give you my green light and go to launch this to production."
- Linear: SAV-495, urgent, In Progress, child of SAV-476.
- Exact base: `437fc6a12356d27b7ad2f9614f89d8c80c073e40`.

## Slice

The ordinary authenticated interview-start workflow issues a signed,
session-bound adaptive admission before LiveKit room creation. The ordinary
Production worker verifies that admission and the exact server-owned rollout
configuration before constructing the reviewed OpenAI Responses Director.
Recommendations still pass through the existing controller, tools, lifecycle,
delivery and transcript authorities.

## Scope

- Production stage `candidate_default`, cohort `canary`, exposure `default`.
- All five interviewer contracts enabled together: brief, controller, tools,
  Director shadow and Director influence.
- Direct OpenAI Responses adapter v1, retry-free, no storage, no tools, exact
  model/provider/base URL, 750 ms request deadline.
- At most ten Director attempts and a conservative 1,000,000,000 nano-USD
  session accounting ceiling.
- Signed room admission bound to session, room, request fingerprint, interview
  deadline, candidate SHA and configuration digest.
- All-off rollback keeps ordinary interviews on the current deterministic
  interviewer and never affects transcript, feedback or credit authority.

## Out of scope

- Changing feedback scoring or claiming that narrow evidence supports scores.
- Giving the Director direct speech, transcript, feedback or credit authority.
- Provider retries, tools, response storage, background execution or customer
  controls for provider/model selection.
- A separate paid LiveKit project or a customer-facing special environment.

## Validation and release

- Freeze contracts/OpenSpec before behavior.
- Provider-free admission, tamper, replay, kill-switch and accounting tests.
- Pinned OpenAI/LiveKit Python tests and repository quality/build gates.
- Exact-range security scan, independent review when available, ready PR and
  terminal hosted CI.
- Protected merge, guarded Production web configuration, guarded ordinary
  Production worker deploy, owner smoke interview, then retain or roll back
  from evidence.
