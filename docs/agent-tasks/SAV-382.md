# SAV-382 Agent Task Intake

## Intent

- User request: Make the authenticated interview lifecycle reliable and fast
  from End Interview through visible feedback completion.
- Product outcome: No candidate remains in an ambiguous saving or feedback
  state. Every wait is bounded, named, measurable, and safely recoverable.
- Why now: Production exposed an indefinite `saving` experience. SAV-381 makes
  transcript evidence durable; this slice closes the remaining orchestration
  and user-visible stale-state gaps.

## Slice

- Primary slice: Lifecycle SLOs and actionable stale-state recovery.
- Secondary slices: Privacy-safe stage telemetry, feedback polling contract,
  user-end redelivery, feedback queue leases, recovery scans, and status UI.
- Relevant skills: LiveKit interview runtime, vertical-slice playbooks, Linear
  workstream, engineering memory, and UI design system.

## Linear Tracking

- Project: Meelni.
- Parent issue: SAV-365.
- Deliverable issue: SAV-382.
- State: In Progress.

## Scope

- In scope: Versioned SLO definitions; normal, delayed, and recoverable status
  classification; stale user-end redelivery; stale sent-but-unclaimed feedback
  recovery; immediate handoff from durable end truth to the feedback lifecycle;
  privacy-safe latency events; polling and UI contracts; runbook and regression
  coverage.
- Out of scope: A new observability vendor, provider internals in customer UI,
  Production alert activation, and changing PM feedback rubrics.
- Assumptions: `ending_at`, `ended_at`, `dispatched_at`, and
  `processing_started_at` are authoritative phase boundaries. Redelivery uses a
  new attempt identity while database claims remain the concurrency fence.

## Technical Plan

- Centralize SLO thresholds and stale-state classifiers.
- Make an `ending/user_end` state directly redeliverable after its terminal
  upper bound using an owner-scoped, minute-bucketed event identity.
- Treat `pending + dispatch_status=sent` as an expiring queue lease. After the
  feedback completion upper bound, atomically prepare a new dispatch attempt;
  an old worker remains fenced by the stored event identity.
- Extend the lifecycle response with bounded `delayed`/`retryable` truth and
  render calm saving, queued, generating, delayed, recoverable, skipped,
  partial, failed, and unavailable states in `FeedbackStatusPage`.
- Transfer presentation ownership from the focused room to the feedback
  workspace as soon as lifecycle truth is `ending` or terminal; server cleanup
  and dispatch gates remain unchanged.
- Emit aggregateable stage latency classifications without transcript,
  question, user, provider, or model content.

## Validation

- Feedback generation-store, recovery-workflow, route, client polling, and UI

- Interview resilience, workflow, typecheck, lint, and build gates.
- Preview-only golden path and alert tuning remain rollout evidence.

## Rollout

- Land contracts and recovery behavior with alerts disabled.
- Rehearse normal, lost-finalizer, sent-unclaimed, slow-generation, skipped,
  partial, and terminal-failure paths in isolated Preview.
- Tune alert thresholds only from Preview and sanitized Production evidence.
