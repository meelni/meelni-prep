# SAV-415 Agent Task Intake

## Intent

- User request: Add a privacy-safe first-party signal that records whether an
  actionable feedback review helped.
- Product/user outcome: A PM candidate can submit or revise one closed
  helpfulness response after reviewing actionable feedback, while Meelni can
  measure aggregate quality without collecting another transcript-like text
  stream.
- Why now: SAV-369, SAV-421, SAV-420, and SAV-418 have established the
  immutable-event, answer-block, four-outcome, and focused-practice seams that
  SAV-415 must consume.

## Slice

- Primary slice: Feedback and evaluation learning loop.
- Secondary slices: Owner-scoped API/data, account privacy, analytics, and
  accessible feedback UI.
- Relevant skills: Meelni feedback evaluation, vertical-slice playbooks,
  codebase architecture, UI design system, engineering memory, Linear
  workstream, and PR prep.

## Linear Tracking

- Project: Meelni.
- Parent slice issue: SAV-410.
- Child deliverable issue: SAV-415.
- Current Linear state: In Progress.

## Scope

- In scope: A closed core contract, separate durable signal table, durable
  owner mutation budget, no-store GET/PUT API, compare-and-swap updates,
  account export/deletion, content-free consent-bound events, privacy-threshold
  aggregation, and an accessible post-review control.
- Out of scope: Free text, support/moderation intake, feedback regeneration,
  scoring changes, transcript/provider payloads, dashboards, provider
  configuration, Production action, deployment, and merge.
- Assumptions: Immutable transcript events remain the integrity source;
  answer blocks remain the evaluation/presentation unit; the existing strict
  completed-feedback presenter remains the only eligibility authority.

## Product Lens

- Audience: Signed-in PM candidates reviewing a completed mock interview.
- Activation/retention/monetization/growth lever: Feedback trust and
  feedback-to-practice retention.
- Product Compass note: The signal measures review usefulness, never candidate
  performance or hiring readiness.

## Technical Plan

- Likely app files: A dynamic owner route under
  `app/api/feedback/[sessionId]/quality-signal/` and the completed-feedback
  composition.
- Likely package/workflow files: `@meelni/core` closed contract and privacy
  aggregator; feedback-quality workflow and Drizzle repository; analytics
  policy/delivery; account export/deletion.
- Data/provider dependencies: Additive Postgres migration. Optional PostHog
  delivery only after explicit current consent. No evaluator or LiveKit call.
- Docs/decisions to update: This intake, OpenSpec delta, feedback-quality
  contract, analytics-consent contract, account-privacy contract, contract
  index, and migration history.

## Validation

- Required commands: Targeted core/workflow/repository/API/component/analytics
  tests, migration lifecycle tests on a disposable loopback database,
  `npm run test:core`, `npm run test:local`, `npm run typecheck`,
  `npm run lint`, `npm run build`, and `npm run verify:agent`.
- Optional/manual checks: Browser verification at 320px, 390px, and desktop;
  keyboard, focus, hydration, saved, stale-conflict, and retry states.
- Fixtures or regression tests needed: Fully synthetic full scorecard, partial
  scorecard, coaching review, unable/corrupt/legacy exclusions, cross-owner,
  exact replay, divergent CAS, deletion races, consent states, and k=9/k=10
  aggregate boundaries.

## Rollout

- Risk level: High because the slice spans auth, privacy, persistence,
  analytics, and a visible feedback surface.
- Backward compatibility: Additive schema and API. Evaluator feedback is never
  updated. Historical formats remain readable but are not relabeled as a
  canonical SAV-420 review outcome.
- Metrics/events to watch: First-party helpfulness cohorts; consented
  `feedback_viewed`, `feedback_helpfulness_responded`, and
  `feedback_practice_started` delivery. All reporting applies the documented
  minimum cohort.
- Follow-up slice: Provider dashboards or product decisions about a revised
  reason taxonomy require a separate issue and contract version.
