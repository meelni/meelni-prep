# SAV-257 Agent Task Intake

## Intent

- User request: remove the fitness framing and revisit the product strategically before relaunch.
- Product/user outcome: Meelni presents evidence-backed PM interview progress without streak pressure, achievement rewards, trophies, badges, or celebration mechanics.
- Why now: the discontinued product is being relaunched and the reward system conflicts with the accepted live PM interview practice positioning.

## Slice

- Primary slice: product simplification and interview-completion workflow.
- Secondary slices: authenticated insights privacy, dashboard/setup UI, account privacy, and data compatibility.
- Relevant skills: product strategy, vertical-slice playbooks, UI design system, engineering memory, Linear workstream, and PR prep.

## Linear Tracking

- Project: Meelni.
- Parent slice issue: relaunch-readiness program.
- Child deliverable issue: SAV-257.
- Current Linear state: In Progress.

## Scope

- In scope: stop streak/achievement writes, remove dead reward UI and APIs, remove derived streak fields, neutralize reward-oriented active icons and tones, prevent authenticated insights caching, preserve historical export/deletion compatibility, retire contradictory agent backlog, and add regression guardrails.
- Out of scope: deleting historical database rows or columns, rewriting migrations, inventing replacement points/rewards, changing providers, enabling the relaunch flag, or taking any Production/live action.
- Assumptions: the product is prelaunch, the removed compatibility APIs have no supported external client, and historical user-owned values must remain exportable until a separately approved retention decision changes export schema `1.0.0`.

## Product Lens

- Audience: PM candidates actively preparing for interviews.
- Activation/retention/monetization/growth lever: retention through trustworthy feedback and a useful next practice action.
- Product Compass note: preserve factual history, score trends with sample context, competency evidence, and recommended next practice; reject a disconnected reward economy.

## Technical Plan

- Likely app files: interview completion, authenticated insights, dashboard analytics, setup difficulty selection, feedback comparison, and dormant reward routes/components.
- Likely package/workflow files: insights aggregation, account export, core product configuration, completion workflow, product-language and design guardrails, and migration verification.
- Data or provider dependencies: local synthetic fixtures and a disposable loopback PostgreSQL test database only; no customer transcripts, Preview mutation, or Production data.
- Docs/decisions to update: accepted positioning, PRD, lifecycle, account privacy, legal product truth, insights API, design examples, and the superseded caching ADR.

## Validation

- Required commands: `npm run check:ci`, `npm run build`, `npm run test:database-migrations`, `npm run test:product-language`, and the design-system guardrail suite.
- Optional/manual checks: after an isolated Preview deployment is available, use only a synthetic account to prove ordinary/deadline completion leaves frozen legacy values unchanged.
- Fixtures or regression tests needed: completion has no reward dependency, insights omit streak fields and use private/no-store, historical streak/achievement values still export, cross-user export rows remain excluded, account deletion cascades legacy achievements, and active reward paths cannot return.

## Rollout

- Risk level: medium; the slice removes dead APIs and changes an authenticated response while simplifying a sensitive completion workflow.
- Backward compatibility: active reward behavior is removed immediately; historical schema and export `1.0.0` remain intact and read-only; physical cleanup is a later expand/contract step.
- Metrics/events to watch: interview completion and feedback-dispatch success, insights API error/latency rates, dashboard analytics errors, and unexpected requests to retired API paths.
- Follow-up slice: consider a versioned export/retention decision and forward-only legacy-schema removal only after relaunch compatibility observation; this is not a relaunch prerequisite.
