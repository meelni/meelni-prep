## Implementation Record

- The seven-stage policy permits adjacent forward promotion only. Every Preview
  and Production forward step requires its own exact candidate/config owner
  authorization.
- Operational rollback is not derived from stage order. Each stage names one
  explicit safe target, including `production_shadow -> disabled` so Production
  never rolls into a Preview influence configuration.
- Only influence revocation is immediate for an active session. Shadow,
  controller, tools, and brief flags govern construction of new sessions; an
  in-flight shadow requires the reviewed settle/shutdown path and rehearsal.
- The readiness report verifies all accepted source digests and fails closed on
  missing, changed, or semantically broadened evidence.
- The report records only current-runtime synthetic baseline/invariants,
  synthetic feedback fixtures, and observability wire cases. It does not claim
  an adaptive quality improvement or any live outcome.
- The v2 request has no selected values or authority. The separately parsed v1
  approved record binds exact adapter/provider/model, integer session/nano-USD
  caps, accepted synthetic-only privacy/retention values, integer bps/ms entry
  and stop thresholds (including first-audio p50/p95), fixed non-tunable stops,
  exact external decision reference, and a maximum seven-day expiry.
- Its domain-separated digest binds authority, stages, candidate SHA, repository
  configuration, and every normalized selection. Parsing proves shape/binding,
  not human identity; the external decision reference remains supervisor/human-
  verified. Rollout-stage and Production-action verifiers reject the record.
- The second live gate's all-round/adverse-voice rehearsal matrix remains
  explicitly unbound and unperformed.
- The system recommendation is `hold_at_synthetic`; owner decision is `pending`.
