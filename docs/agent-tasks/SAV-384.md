# SAV-384 Agent Task Intake

## Intent

- User request: Make the authenticated interview lifecycle reliable and fast
  from launch through durable feedback.
- Product outcome: A candidate either enters a canonically ready room inside a
  bounded wait or sees an honest delayed state with a safe exit. A stalled
  dependency cannot leave setup or the room spinning for minutes.
- Why now: The post-interview tail is bounded, but the launch client and
  canonical readiness probes remain unbounded. Provider readiness exhaustion
  currently turns a connected LiveKit transport into unnecessary token churn.

## Slice

- Primary slice: Bounded interview launch and canonical runtime readiness.
- Secondary slices: Start/readiness SLO policy, privacy-safe stage telemetry,
  delayed-room UI, credential-read deadlines, and connection-state truth.
- Relevant skills: LiveKit interview runtime, vertical-slice playbooks, Linear
  workstream, engineering memory, and UI design system.

## Scope

- In scope: Abortable setup launch; bounded session, token, and presence reads;
  a readiness budget that accommodates the documented 10–20 second LiveKit
  Cloud cold start; delayed readiness without reconnect churn; honest status
  copy; End Interview availability; telemetry and regression tests.
- Out of scope: Weakening provider-verified activation, changing transcript
  persistence, deploying to Production, enabling the relaunch gate, or changing
  LiveKit capacity.
- Assumptions: LiveKit transport and canonical interview readiness remain
  distinct. A retryable readiness timeout is not evidence that the participant
  token or transport is invalid.

## Technical Plan

- Centralize start/readiness thresholds and latency classification.
- Bound the setup start request while preserving the stable start-attempt UUID
  so an ambiguous response can be safely replayed.
- Give each presence request a short abort deadline and the overall readiness
  confirmation a single upper bound. Treat authorization loss as terminal but
  treat dependency/cold-start exhaustion as delayed.
- Keep a connected room mounted when readiness is delayed. Do not request a new
  token unless the LiveKit transport itself disconnects.
- Render canonical readiness in the connection indicator, retain End Interview,
  and explain that the interviewer is still joining after the upper bound.
- Emit only versioned stage, outcome, duration, threshold, and latency-class
  fields.

## Rollout

- Land with the relaunch gate unchanged and alerts disabled.
