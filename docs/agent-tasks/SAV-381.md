# SAV-381 Agent Task Intake

## Intent

- User request: Make the authenticated interview lifecycle reliable from live
  transcript capture through end-of-interview feedback.
- Product/user outcome: Feedback is generated from one immutable, database-
  proven transcript prefix even if the final LiveKit settlement exchange is
  unavailable.
- Why now: The Production incident showed that already-persisted turns could be
  discarded for feedback solely because the end-time settlement round trip was
  deferred.

## Slice

- Primary slice: Transcript committed watermarks and frozen feedback evidence.
- Secondary slices: terminal eligibility, feedback transcript reads, recovery,
  database migration, and redacted lifecycle telemetry.
- Relevant skills: LiveKit interview runtime, vertical-slice playbooks, Linear
  workstream, and engineering memory.

## Linear Tracking

- Project: Meelni.
- Parent slice issue: SAV-365.
- Child deliverable issue: SAV-381.
- Current Linear state: In Progress.

## Scope

- In scope: Per-writer contiguous progress, durable integrity health, additive
  schema/backfill, terminal cutoff snapshots, complete/partial/insufficient/
  degraded classification, snapshot-bounded evaluation reads, compatibility,
  and replacement/reconnect/gap fixtures.
- Out of scope: Browser transcript persistence, rubric or prompt changes,
  Production migration/deployment, and relaunch-gate changes.
- Assumptions: Runtime writer sequence is stable within one generation;
  transcript and terminalization transactions continue to serialize on the
  session row; partial feedback already has a product/UI contract and must use
  the existing minimum eligibility policy.

## Technical Plan

- Extend each runtime writer with the highest observed sequence, highest
  contiguous committed sequence, committed boundary identity/time, integrity
  state, and database progress time.
- Advance the watermark in the same transaction that persists a turn or marker.
  Out-of-order writes do not advance across a gap; filling a gap converges the
  already-persisted suffix.
- At terminalization, freeze the semantic cutoff and one per-writer snapshot.
  Complete evidence requires settled proof no later than the terminal cutoff
  from every writer. The active ending writer is constrained to the exact
  terminal cutoff; fenced generations retain their earlier handoff cutoff.
  Healthy, gap-free persisted evidence without settlement may produce
  bounded partial feedback only when the existing partial threshold passes.
- Make feedback generation read only rows at or below each frozen writer
  watermark and at or before the frozen cutoff. Legacy rows retain a bounded
  dual-read path.

## Validation

- Required commands: focused transcript/finalizer/generation tests, package
  tests, Python runtime contract tests, interview resilience, database migration
  tests when disposable PostgreSQL is available, typechecks, lint, and build.
- Regression fixtures: in-order writes, out-of-order gap and healing, replay,
  cross-kind sequence conflict, replacement writers, missing settlement,
  degraded settlement/marker, immutable snapshot reads, and legacy fallback.
- Manual: isolated Preview interview proving persisted progress, end with a
  deliberately unavailable settlement exchange, partial feedback generation,
  and no post-cutoff evidence consumption.

## Rollout

- Risk level: High. This changes transcript eligibility and adds terminal
  evidence state, but keeps all changes additive and fail-closed on corruption.
- Backward compatibility: Existing sessions without a versioned snapshot use
  the bounded legacy read. New sessions write the versioned snapshot atomically.
- Metrics to watch: watermark gap/degraded counts, evidence-state distribution,
  terminalization latency, feedback dispatch/completion latency, and skipped
  feedback reason.
- Rollback: Keep the additive columns/table and restore legacy application reads;
  never delete frozen evidence or reopen terminal sessions.
