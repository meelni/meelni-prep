# SAV-445 Agent Task Intake

## Intent

- User request: Define a versioned, default-off shadow feedback artifact and
  additive storage seam after trusted block authority and evaluator budgets
  landed.
- Product/user outcome: Future incremental evaluation can be measured without
  changing customer feedback, insights, billing, or batch authority.
- Why now: The accepted interview-to-feedback program requires an immutable,
  deletion-aware key/storage boundary before any shadow execution is allowed.

## Slice

- Primary slice: Feedback evaluation integrity and provider-neutral storage.
- Secondary slices: Database privacy lifecycle and durable contract memory.
- Relevant skills: Linear workstream, feedback evaluation, codebase
  architecture, feedback vertical-slice playbook, engineering memory, and PR
  prep.

## Linear Tracking

- Project: Meelni.
- Child deliverable issue: SAV-445.
- Current Linear state: In Progress.

## Scope

- In scope: Versioned artifact key/value/set parsers, content-minimized result
  shape, opaque default-off write gate, immutable exact-key store, additive
  migration 0039, exact-key reads, account export/deletion/retention behavior,
  and provider-free fixtures.
- Out of scope: Scheduling, evaluator/provider calls, comparison reports,
  feedback lifecycle integration, UI, insights, billing, Production mutation,
  deployment, provider configuration, spend, and activation.
- Assumptions: The SAV-441 trusted identity is the only block fingerprint input;
  migration 0038 is the exact merged predecessor.

## Product Lens

- Audience: PM candidates whose saved interview data may later participate in
  an owner-authorized shadow measurement.
- Product lever: Feedback trust and delivery quality, without a customer-facing
  behavior change in this slice.
- Product Compass note: Preserve the final batch evaluator as the sole feedback
  authority while making future experiments replay-safe and privacy-complete.

## Technical Plan

- Core: Strict key, artifact, failure, metrics, and exact-set contracts.
- Server: Runtime-minted storage enablement context and a single gated write
  entrypoint plus gated exact reads; disabled and forged gates return before
  repository access. Production capability minting reads only `process.env`.
- Data: Separate service-only table with a SHA-256 primary key, exact tuple
  uniqueness, owner/session correlation, bounded JSON, immutable insert
  semantics, and no feedback foreign key.
- Privacy: Allowlisted export, explicit deletion before the session graph, and
  owner/session cascade defense. No shorter expiry is invented without an
  owner retention decision.
- Docs: Contract, architecture status, OpenSpec, privacy, and migration
  inventories.

## Validation

- Required commands: Targeted core/store/config/privacy tests, migration
  collision checks, database migration rehearsal, typecheck, build, and
  `verify:agent`.
- Fixtures: Crash-after-insert replay, duplicate event delivery, reconnect,
  1/2/5/10 segmentation, version change, conflicting payload, unknown version,
  deletion, export, and disabled zero-side-effect behavior.
- Manual audit: No imports or calls from generation, Inngest, feedback reads,
  UI, insights, billing, or provider adapters.

## Rollout

- Risk level: Medium; additive persistence is durable but structurally
  default-off and non-authoritative.
- Backward compatibility: Existing feedback/session rows and all batch paths
  are unchanged. Unknown artifact versions fail closed.
- Activation: No default-on, Preview/Production migration, deployment, or
  provider action is authorized by this change.
