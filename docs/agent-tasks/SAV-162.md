# SAV-162 — Telemetry and headless QA noise

## Outcome

Browser QA and local product checks should distinguish launch-relevant UI
regressions from telemetry/runtime noise.

## Scope

- Route Statsig SDK exception reporting through the existing consent-gated
  same-origin proxy instead of allowing the browser SDK to hit
  `statsigapi.net` directly.
- Preserve strict rejection for unsupported Statsig endpoints.
- Keep web-vitals reporting bundled through `next/web-vitals`; do not allow the
  legacy `unpkg.com/web-vitals` script loader to return.
- Document expected LiveKit-only headless limitations without broadening the
  browser-QA blocking contract.

## Validation

- `./node_modules/.bin/vitest run 'app/api/statsig/[endpoint]/route.test.ts'`
- `./node_modules/.bin/tsx --test lib/analytics/use-web-vitals.test.ts`

## Notes

No external provider configuration was changed. Relaunch feature flags remain
off by default outside the isolated browser-QA environment.
