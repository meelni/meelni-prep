# SAV-419 Agent Task Intake

## Intent

- User request: Close the Production settlement-target resolution edge left by
  SAV-412 and make every post-End local evidence callback cutoff-aware.
- Product/user outcome: A healthy current interview runtime receives one exact
  trusted End packet, preserves the candidate's measured in-progress answer,
  durably settles its writer generation, and makes no late or unmeasured
  transcript request after End.
- Why now: A sanitized post-rollout interview had a gap-free 15/15 writer but
  no runtime settlement. The workflow returned `runtime_not_ready` before the
  minimum acknowledgement-poll interval, followed by one locally drainable
  turn rejected by the already terminal web route. Cleanup left no historical
  provider projection to inspect; the real-protobuf fixtures are the smallest
  Production-shaped coverage for that proven pre-send boundary, not a claim
  about the deleted room's exact payload.

## Slice

- Primary slice: Authenticated LiveKit runtime settlement.
- Secondary slices: Provider normalization, transcript callback fencing,
  privacy-safe operations telemetry, and feedback handoff reliability.
- Relevant skills: LiveKit interview runtime, codebase architecture,
  vertical-slice playbooks, feedback evaluation, engineering memory, Linear
  workstream, and PR prep.

## Scope

- In scope: Normalize pinned AgentDispatch/Job protobuf state, accept only one
  exact current room job, recheck the durable generation before send, install
  the local callback and session fence before task scheduling, and emit closed
  identity-free settlement-stage telemetry.
- Out of scope: Feedback eligibility changes, provider mutation, Production
  deployment, historical repair, participant publish authority, demo runtime,
  and launch authorization.
- Assumptions: RoomService participant presence is authoritative when exact;
  AgentDispatch is a narrow fallback only when its current job proves the same
  room, configured agent, running state, and bounded participant identity.

## Product Lens

- Audience: PM candidates ending an authenticated interview.
- Activation/retention lever: Preserve trust that End saves the completed
  interview evidence and leads to feedback.
- Product Compass note: End is a hard conversational cutoff; feedback remains
  post-interview and never runs on unproven evidence.

## Technical Plan

- Normalize real pinned protocol classes and fail closed on malformed,
  ambiguous, pending, stale, wrong-room, wrong-agent, or conflicting facts.
- Re-read the exact writer generation after target resolution and before the
  exact-destination server packet.
- Reserve the settlement request identity, synchronously install the exact
  cutoff-aware callback gate plus input/output/speech fence, then create the
  asynchronous drain task. During drain only canonical candidate or confirmed
  interviewer evidence measured at or before the cutoff, plus preauthorized
  integrity facts with exact occurrence, is admitted; settlement closure
  rejects every callback.
- Keep telemetry versioned, fixed, identity-free, and nonblocking.
- Update runtime contracts, operations notes, and active OpenSpec artifacts.

## Validation

- Required commands: Focused integration/workflow/telemetry tests; Python
  runtime contracts; agent, integration, workflow, resilience, database
  lifecycle, typecheck, lint/build, and `verify:agent` gates.
- Regression fixtures: Separate real protobuf history and current one-job
  dispatches; a mixed history/current room dispatch; malformed
  bigint defaults and identities; ambiguity; provider failure; writer
  replacement; duplicate End; partial fence retry; hung control lane; durable
  settlement with measured candidate evidence before the metadata-only row and
  zero late, unmeasured, post-gate, or post-settlement HTTP attempts.

## Rollout

- Risk level: High because this joins provider targeting to the terminal
  transcript boundary.
- Backward compatibility: Packet schema, participant grants, writer identity,
  database schema, feedback policy, and terminal arbitration are unchanged.
- Metrics/events to watch: Closed target-resolution, generation-recheck,
  packet-send, packet-validation, local-fence, drain, settlement-persist, and
  durable-ack stages.
- Follow-up slice: Owner-authorized authenticated Production interview and
  feedback proof; SAV-370 owns broader funnel alerts/canaries.
