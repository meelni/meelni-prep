# SAV-252 Agent Task Intake

## Intent

- User request: Operationalize the SAV-251 semantic gate without making a
  provider call or creating future spend authority.
- Product/user outcome: Synthetic feedback bytes can be reviewed by two
  independent agent executions while public evidence remains content-free.
- Why now: The contract exists, but capture, trusted receipt plumbing,
  retention, and sanitized publication were not yet one fail-closed workflow.

## Slice

- Primary slice: Feedback/evaluation reliability.
- Secondary slice: Agent review governance.
- Relevant skills: `meelni-feedback-evaluation`,
  `meelni-vertical-slice-playbooks`, `meelni-engineering-memory`, and
  `meelni-linear-workstream`.

## Linear Tracking

- Project: Meelni.
- Parent slice issue: SAV-198.
- Child deliverable issue: SAV-252.
- Current state: Owned by the root work stream; this scoped implementation
  makes no external Linear mutation.

## Scope

- In scope: Private `0700` capture, `0600` byte-exact outputs, opaque IDs,
  full run/input/case-run bindings, trusted two-execution receipt authority,
  SAV-251 validation, sanitized publication, cleanup, and mutation tests.
- Out of scope: Provider/paid calls, customer or Production data, reviewer
  prose, human identity, a new v3 plan, spend authorization, or launch approval.
- Assumption: The trusted operator/orchestrator verifies that receipts came
  from two actual completed agent tasks before constructing execution
  authority. Self-authored panel JSON is never provenance.

## Technical Plan

- Workflow: `lib/evaluation/calibration-semantic-capture.ts` delegates all
  semantic decision rules to the SAV-251 validator.
- Provider dependencies: None.
- Durable docs: Evaluation-calibration runbook only; no new ADR.

## Validation and rollout

- Required: Targeted provider-free tests, calibration suite, and non-incremental
  typechecks when disk permits.
- Regression fixtures: Passing E2E plus subset, byte/hash, manifest/path,
  receipt/provenance, disagreement, semantic rejection, and publication
  failures.
- Risk: Medium operator-tooling risk; no customer runtime behavior changes.
- Rollback: Remove the local workflow. SAV-251 and historical v1/v2 evidence
  remain unchanged.
