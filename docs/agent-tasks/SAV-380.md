# SAV-380 Agent Task Intake

## Intent

- User request: Audit and harden the authenticated interview lifecycle from
  room entry through transcript persistence, explicit end, and feedback.
- Product/user outcome: A slow dependency cannot make the interview or
  feedback surface hang, and one browser cannot multiply the failure.
- Why now: A Production interview accepted End quickly but repeated transcript
  and feedback reads remained open until the platform's 300-second ceiling.

## Slice

- Primary slice: Interview transcript and feedback read path.
- Secondary slices: Supabase auth transport, Postgres runtime limits, lifecycle
  observability.
- Relevant skills: codebase architecture, LiveKit interview runtime, feedback
  evaluation, vertical-slice playbooks, Linear workstream, engineering memory.

## Linear Tracking

- Project: Meelni.
- Parent slice issue: SAV-365.
- Child deliverable issue: SAV-380.
- Current Linear state: In Progress.

## Scope

- In scope: One initial transcript hydration, reconnect-only resync, abortable
  client reads, bounded server auth/query/route work, retryable 503 responses,
  privacy-safe regression coverage.
- Out of scope: Transcript evidence policy, feedback scoring, LiveKit
  turn-taking, Production deployment, and provider credential changes.
- Assumptions: Runtime packets remain post-persistence display notifications;
  the database remains canonical transcript and lifecycle truth.

## Product Lens

- Audience: Candidates completing authenticated PM mock interviews.
- Lever: Trust and completion reliability.
- Product Compass note: The UI must remain responsive without weakening the
  evidence required for feedback.

## Technical Plan

- Remove agent-state transitions from transcript hydration ownership.
- Hydrate once per owner/session and resync after an actual recovered
  connection, with cancellation and a client deadline.
- Apply a bounded fetch to feedback polling and recovery.
- Bound Supabase server fetches, transaction-local database statements, and the
  two customer read routes below Vercel's function duration.
- Return typed retryable responses with `Retry-After` for dependency deadlines.

## Validation

- Required commands: targeted interview page, feedback page, transcript API,
  feedback API, HTTP deadline, database option, typecheck, and lint checks.
- Regression fixtures: repeated agent state changes, reconnect during a pending
  hydration, stalled feedback GET, stalled auth, and database statement timeout.
- Privacy: No session identifier, user identity, transcript content, provider
  payload, or credential from Production enters the repository.

## Rollout

- Risk level: Medium. Transaction-local query timeouts and route/client
  deadlines affect the two customer-visible read paths.
- Backward compatibility: Response success contracts are unchanged; transient
  dependency failures become retryable 503s.
- Metrics to watch: transcript/feedback read duration, 503 rate, overlapping
  request count, and lifecycle completion latency.
