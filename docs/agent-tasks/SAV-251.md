# SAV-251 Agent Task Intake

## Intent

- User request: Define a safe semantic review path for synthetic calibration
  outputs before any future v3 provider run.
- Product/user outcome: Calibration can distinguish useful, defensible PM
  feedback from merely grounded output without retaining provider content in
  public evidence.
- Why now: SAV-248 stopped on an invalid response and an unmatched canonical
  anchor; SAV-250 proved that all 32 transcripts admit legitimate alternatives.

## Slice

- Primary slice: Feedback/evaluation reliability.
- Secondary slices: Agent review governance and release evidence.
- Relevant skills: `meelni-feedback-evaluation`,
  `meelni-linear-workstream`, `meelni-engineering-memory`.

## Linear Tracking

- Project: Meelni.
- Parent slice issue: SAV-198.
- Child deliverable issue: SAV-251.
- Current Linear state: Owned by the parent work stream; external updates are
  handled by the root agent.

## Scope

- In scope: A versioned, provider-free contract and validator; a separate
  trusted operator/orchestrator authority envelope; exact run,
  corpus, prompt/schema, model, response-set, and per-response hash binding;
  two independent closed-decision agent panels; sanitized public reporting;
  mutation tests; contract and operator documentation.
- Out of scope: Provider calls, paid calls, Production/customer data, a v3
  spend authorization, live-run integration, and any assertion that a future
  output has already been reviewed.
- Assumptions: Future synthetic raw outputs remain in an operator-controlled
  private directory and are reduced to byte-exact hashes before review
  artifacts enter the repository.

## Product Lens

- Audience: PM candidates and the operators responsible for trustworthy
  feedback quality.
- Lever: Retention and trust through PM-calibrated, actionable feedback.
- Product Compass note: A grounded quote alone is not proof that feedback is
  relevant, accurate, useful, or assigned to the right rubric dimension.

## Technical Plan

- Likely app files: None.
- Likely package/workflow files:
  `lib/evaluation/calibration-semantic-adjudication.ts` and its behavior tests.
- Data or provider dependencies: None.
- Docs/decisions to update: Evaluation-calibration contract and runbook. No new
  ADR is needed because this narrows an existing calibration gate.

## Validation

- Required commands: Targeted Node 22 tests, calibration tests, typecheck, and
  test typecheck.
- Optional/manual checks: Inspect a generated public report for absence of raw
  response, transcript, prompt, and reviewer prose.
- Fixtures or regression tests needed: Valid unanimous review plus mutations
  for missing/duplicate outputs, forged hashes, panel disagreement,
  contradictory decisions/prose, duplicate panel identity, and unreviewed
  legitimate alternatives.

## Rollout

- Risk level: Medium; this is a future launch-evidence gate, not runtime
  customer behavior.
- Backward compatibility: Existing v1/v2 historical calibration artifacts are
  immutable and are not reinterpreted.
- Metrics/events to watch: Not applicable until a separately authorized future
  calibration integrates the contract.
- Follow-up slice: Bind a separately reviewed v3 plan and private output
  capture flow only after this contract is accepted; that work requires a new
  authorization.
