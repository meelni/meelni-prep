# SAV-359 Agent Task Intake

## Intent

- User request: Redesign the mobile public and authenticated navigation, replace the bottom-up menu interaction, and keep starting a new interview persistently easy.
- Product/user outcome: PM candidates can orient themselves and launch practice quickly from any mobile workspace screen.
- Why now: Global navigation currently behaves like a contextual bottom sheet, while signed-in mobile chrome compresses hierarchy and action into a crowded top row.

## Slice

- Primary slice: Responsive mobile navigation.
- Secondary slices: Accessibility, safe-area behavior, and browser QA.
- Relevant skill(s): `meelni-ui-design-system`, `meelni-design-review-orchestrator`.

## Linear Tracking

- Project: Meelni.
- Parent slice issue: SAV-358.
- Child deliverable issue: SAV-359.
- Current Linear state: In Progress.

## Scope

- In scope: Shared left-side navigation drawer, public navigation composition, authenticated workspace composition, persistent New Mock Interview action, route/current state, focus and dismiss behavior, regression coverage.
- Out of scope: Desktop navigation, live interview-room chrome, route taxonomy, and task-local bottom drawers.
- Assumptions: Left-side entry best matches global hierarchy and right-handed reach because opening remains in the top-right while destinations form a stable left rail; bottom sheets remain contextual controls.

## Product Lens

- Audience: PM candidates practicing on mobile web between meetings, commutes, and active interview preparation.
- Activation/retention/monetization/growth lever: Faster return to the core practice action and stronger discovery-to-product continuity.
- Product Compass note: Keep the interface tactical and trustworthy; navigation should reduce cognitive load and never compete with interview content.

## Technical Plan

- Likely app files: `components/mobile-drawer.tsx`, `components/dashboard/layout/dashboard-mobile-navigation.tsx`, targeted tests.
- Likely package/workflow files: New shared primitive under `components/ui/`; no package-layer changes.
- Data or provider dependencies: Existing auth provider, activation decision, and route state.
- Docs/decisions to update: Product container audit/canonical pattern only if the shipped shell contract changes materially.

## Validation

- Required commands: Targeted navigation tests, `npm run typecheck`, `npm run lint`.
- Optional/manual checks: Landing and authenticated workspace at 320px, 390px, and 430px; open/close, Escape, overlay, focus, route links, safe area, and horizontal overflow.
- Fixtures or regression tests needed: Open public and dashboard navigation at a mobile viewport.

## Rollout

- Risk level: Medium; shared navigation chrome is highly visible but provider/data behavior is unchanged.
- Backward compatibility: Preserve routes, activation gating, desktop sidebar, and existing task-local drawers.
- Metrics/events to watch: New Mock Interview entry from mobile chrome, menu opens, navigation exits, and abandonment before setup.
- Follow-up slice: Add the two open-menu states to the representative browser QA matrix if the current harness cannot express them in this pass.
