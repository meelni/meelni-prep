# Account Data Export Operations

Account export is a synchronous, read-only JSON download generated by
`GET /api/user/export`. The route authenticates first, loads only that user's
allowlisted fields, applies the `1.5.0` export contract, and sends the attachment
without writing a server-side export file.

An ordinary HTTP 401 means the session is absent or expired. The Data & privacy
surface offers a safe sign-in redirect back to the same section instead of a
generic export retry. Once `account_deletion_pending` is durable, middleware
blocks further export and the UI treats that response as deletion-state truth.

## Provider and data safety

- No Supabase Admin or Stripe API call is required.
- Never query through a service-role browser client or expose server env values.
- Keep the database adapter user-scoped and use explicit selected columns.
- Do not add raw provider rows, webhook payloads, error text, metadata,
  idempotency values, receipt URLs, or provider resource identifiers.
- Do not log the export body, transcripts, feedback, email, or failure object.
- Keep `Cache-Control: private, no-store` and `X-Content-Type-Options: nosniff`.

## Contract changes

Additive or breaking payload changes require:

1. updating the `@meelni/core` schema version and types;
2. updating `docs/contracts/account-privacy.md` inclusions/exclusions;
3. updating the reusable fixture and workflow/API tests; and
4. verifying older downloaded JSON remains understandable or documenting the
   migration boundary.

## Verification

- Unauthenticated requests return 401 before any data read.
- A fixture export includes only the requested user's account and practice data.
- Nested secret/provider-shaped keys are absent from the serialized payload.
- Billing output contains user-facing summaries but no Stripe IDs, webhook
  payloads, error text, metadata, idempotency keys, or receipt URLs.
- The response downloads as JSON and is not cached.
- A forced data-layer error returns the stable `account_export_failed` response
  without provider, SQL, credential, or customer details.

Shared Preview and Production accounts are not disposable test fixtures. Use
unit/API fixtures and a local disposable database for integration rehearsal.
